# 单词熟练度算法

本文档说明当前单词熟练度分数、等级和抽词优先级的计算方式。实现位置：`apps/web/src/lib/masteryCalculator.ts`。

## 目标

熟练度分数用于表示用户对某个单词的长期掌握程度；抽词优先级用于决定练习时更应该出现哪些单词。两者语义不同：熟练度不直接因为几天没练而下降，但长期未练会显著提高抽词优先级。

## 数据字段

每个单词会记录以下练习数据：

- `correctCount`：正确输入次数。
- `totalAttempts`：总尝试次数，只在一次输入已经完成时统计；正确输入、看提示、输入长度达到单词长度但仍不匹配都会计入，尚未输完的中间状态不会计入。
  - **错误输入按「尝试」计数**：每次「从不满长度重新输到满长度且仍不匹配」计一次（清空/回退重算新的尝试，原地修正不重复计）。
  - **看提示按「轮」去重**：每个词每轮（每次抽取的练习批次）最多记一次，避免 hover/focus 连发重复计数。
- `inputTimes`：最近若干次**单词拼写练习**的正确输入耗时（秒）。造句练习没有真实输入计时，`recordCorrectAttempt` 不传 `inputTimeSeconds`，因此该字段只来自拼写练习；上限 20 条，超限保留最近记录。
- `lastPracticedAt`：最近一次练习时间（无论对错）。
- `correctPracticeDates`：发生过正确输入的本地日期列表，保存为 `YYYY-MM-DD` 格式的本地日期字符串（`formatLocalPracticeDate`），不存 ISO 时间戳，避免时区解析偏移；同一天去重，上限 30 条。

## 熟练度分数

总分范围为 0 到 100，由四个子分数组成：

| 因素 | 权重 | 说明 |
| --- | --- | --- |
| 正确率 | 50% | 使用平滑后的 `correctCount / totalAttempts`，降低小样本波动 |
| 输入速度 | 15% | 使用最近 5 次正确输入耗时，与按单词长度估算的期望时间比较 |
| 稳定性 | 20% | 使用最近 10 次输入耗时的变异系数（MAD 版本），越稳定分数越高 |
| 跨天复习 | 15% | 根据有正确输入记录的本地自然日数量计算，最多按 3 天给满分 |

**因子可用性**：没有足够数据的因子不参与总分加权，权重按可用因子归一化（分母 = 可用因子权重之和）。具体规则：

- 输入速度：没有拼写计时数据（如纯造句练习的词）或最近 5 次全部被判定为异常时，该因子不计入总分；`speedScore` 返回中性展示值 20。
- 稳定性：少于 3 个计时样本时不参与加权，`consistencyScore` 返回默认展示值 50。
- 正确率、跨天复习始终参与。

因此造句为主的词也能通过「多次且跨天的正确练习」达到 mastered，不会因为缺少打字计时而被永久压级。

各子分数计算细节：

- **正确率**：`(correctCount + 1) / (totalAttempts + 2) × 100`（拉普拉斯平滑）。
- **输入速度**：取最近 5 次耗时的均值，先剔除明显异常样本（`耗时 > 期望时间 × 5`，如练习中切走/中断造成的超长耗时），再与期望时间比较：`期望时间 ÷ 平均耗时 × 50`，限制在 0–100。
- **稳定性**：取最近 10 次耗时，用中位数绝对偏差（MAD）计算变异系数 `cv = MAD ÷ 中位数`（对单次中断异常不敏感），`100 × e^(-2·cv)`，限制在 0–100。
- **跨天复习**：对 `correctPracticeDates` 按本地日期去重后 `天数 × 100/3`，超过 3 天按 100 封顶。

## 等级门槛

分数对应等级如下：

| 等级 | 分数范围 |
| --- | --- |
| new | 0-19 |
| learning | 20-39 |
| familiar | 40-59 |
| proficient | 60-79 |
| mastered | 80-100 |

此外还会按练习次数和跨天正确记录设置等级上限：

- 少于 3 次尝试：最高 `learning`。
- 少于 5 次尝试，或少于 2 个正确复习日：最高 `familiar`。
- 少于 8 次尝试，或少于 3 个正确复习日：最高 `proficient`。

因此，单词不能只靠同一天连续输入几次就进入 `mastered`，必须经过多次且跨天的正确复习。

## 抽词优先级

抽词优先级越高，练习时越容易被选中。它由三部分组成（实现：`calculatePriority`）：

```
优先级 = 基础优先级 × 时间倍率 × 练习次数倍率
```

| 部分 | 规则 |
| --- | --- |
| 基础优先级 | `max(10, 100 - 熟练度)`，熟练度越低越高；即使熟练度是 100，也保留最低基础优先级 10，避免永远不复习 |
| 时间倍率 | 距离上次练习越久越高：<1 天 `0.3`，1–2 天 `0.8`，2–4 天 `1.2`，4–7 天 `2.0`，7–14 天 `8.0`，14 天以上 `15.0`（封顶，不再增长） |
| 练习次数倍率 | 新词与低练习次数更高：0 次 `3.0`，1–2 次 `2.0`，3–5 次 `1.5`，6–10 次 `1.0`，11 次以上 `0.8` |

## 调参原则

- 如果用户觉得熟词出现太频繁，优先降低 7 天以上的时间倍率。
- 如果用户觉得单词太容易变成 `mastered`，优先提高 mastered 的尝试次数或正确复习日门槛。
- 如果用户觉得打字速度影响过大，继续降低速度权重并把权重分配给正确率或跨天复习。
- 如果用户觉得中途中断造成的一次超长耗时影响了分数，检查稳定性（MAD）与速度异常值过滤的阈值。

## 已知限制与演进方向

- **熟练度不代表记忆状态**：熟练度不随时间衰减，长期未练只反映在抽词优先级上。若需要类似 Anki/SM-2 的「记忆强度」，需在现有字段基础上加入动态复习间隔和 ease factor。
- **正确率是累积统计**：早期错误会长期影响正确率。若要更灵敏地反映「近期生疏」，需引入对错序列数据（如 `attemptHistory`）并做近期正确率加权。
- **抽词时间倍率是分段阶梯**，在 7 / 14 天边界存在跳变；当前刻意保持简单可解释，若要平滑需同步更新上面的数值表。
- **同步为「最后写入者胜」**：多设备并发练习同一单词时，后同步的设备会覆盖先同步设备的结果（同步队列条目是全量快照）。multi-device 增量合并属于独立演进方向。
